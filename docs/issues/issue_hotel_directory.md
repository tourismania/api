## Контекст

Менеджеры агентства собирают офферы с одними и теми же отелями и каждый раз заново вводят описания
и ищут фото. Справочник отелей агентства с категориями номеров даёт диалогу отеля в оффере
подгрузить описание, фото и категории. Это первая половина задачи «отели оффера»; создание записей
справочника приходит со второй (`add-offer-hotels`).

**Инварианты:**

- **Отель принадлежит агентству и виден только ему.** Агентство берётся из текущей записи
  пользователя при каждом запросе; обхода для `ROLE_SUPER_ADMIN` нет; чужой отель неотличим от
  несуществующего (`404 hotel not found`). Читать может любой пользователь агентства.
- **Категория номера существует только у своего отеля**; у отеля может не быть категорий.
  Название категории **уникально в пределах отеля** без учёта регистра среди действующих
  категорий (ревью api PR №39): удалённая категория название не занимает; повтор —
  `hotel.ErrRoomCategoryNameTaken` (→ `400`).
- **Создание — только доменная операция** (`hotel.New`, `hotel.NewRoomCategory`,
  `Repository.Insert*`), без эндпоинта: её вызывает сохранение оффера в своей транзакции. Роль
  фабрики не проверяют — права проверяет команда оффера.
- **Мягкое удаление** (`deleted_at`): все чтения фильтруют удалённые; категории удалённого отеля
  скрыты вместе с ним; эндпоинта удаления нет.
- **Общие правила полей** — `domain/content` (текст без управляющих символов, кроме `\t\n\r`;
  ссылки фото — абсолютные `http(s)` с хостом), ими же пользуется позиция оффера. Звёзды 0–5 —
  правило отеля, живут в `domain/hotel` (ревью api PR №39).

## Эндпоинты

| # | Метод | Путь | Доступ | Успех |
|---|---|---|---|---|
| 1 | `GET` | `/api/v1/hotels?search=&limit=&offset=` | JWT, любая роль, своё агентство | `200` |
| 2 | `GET` | `/api/v1/hotels/{id}/room-categories` | JWT, любая роль, своё агентство | `200` |

1. Поиск по подстроке названия без учёта регистра, буквально (`%`, `_`, `\`); от 2 символов после
   нормализации пробелов, иначе `400 INVALID_SEARCH`; сначала начало названия, затем подстрока,
   внутри — название, `id`. Пагинация как у авиакомпаний. Элемент — `id, name, stars, address,
   description, photo_urls`, без категорий. `Cache-Control: no-store`.
2. Все категории в порядке создания, без пагинации: `id, name, description, photo_urls`. `{id}` не
   целое ≥ 1 → `400 invalid hotel id`; чужой, удалённый, несуществующий → `404 hotel not found`.
   `Cache-Control: no-store`.

## Хранение

- **Логика — не в БД** (ревью api PR №39, `STYLE.md` §12): без `CHECK`, правила значений — в домене.
- `024_create_hotels` — `hotels` (агентство, название, звёзды, адрес, описание,
  `photo_urls text[]`, `created_at`, `deleted_at`), индекс `(agency_id, lower(name))` по
  действующим.
- `025_create_hotel_room_categories` — `hotel_room_categories` (отель, название, описание, фото,
  `created_at`, `deleted_at`), уникальный индекс `(hotel_id, lower(name))` по действующим;
  репозиторий переводит его нарушение в `hotel.ErrRoomCategoryNameTaken`.
- Запросы — `queries/hotels.sql`; слой `db/hotels.sql.go` написан вручную в форме sqlc, как остальной
  `db/` (см. `db/db.go`), с теми же явными циклами чтения строк.

## Ревью api PR №39

- Именование: use case `query/get_room_categories`, хендлер `hotel/get_room_categories`, поля
  `GetRoomCategories`; правило — `STYLE.md` §1 «Use case'ы и HTTP-хендлеры».
- Нормализация строки поиска — `application/helpers.NormalizeSearch` (общая с авиакомпаниями).
- Глаголы чтения зафиксированы в `STYLE.md` §1: `get` — один объект или фиксированный набор,
  принадлежащий объекту, без пагинации и фильтров; `list` — коллекция целиком с необязательными
  фильтрами и пагинацией в стабильном порядке; `search` — по обязательной строке поиска с
  ранжированием по релевантности (критерий — не пагинация). Существующий код приведён к правилу: `query/get_offers` →
  `query/list_offers`, `offer/get_list` → `offer/list`, `offer/get_public` → `offer/get_published`;
  поля `GetOffers` → `ListOffers`, `Airports` → `SearchAirports`, `Currencies` → `ListCurrencies`;
  пакеты хендлеров — имя use case + `http` (`searchairlineshttp`, `searchairportshttp`,
  `searchhotelshttp`, `getpublishedofferhttp`). Маршруты и контракт не менялись.

- Цены, даты и описания для клиента — данные позиции оффера (`add-offer-hotels`).
- Загрузка и хранение файлов фото.
