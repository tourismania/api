# [feat] Номер рейса сегмента перелёта (Flight) в составе Offer

> **Зависит от:** sdd `add-flight-segment-airline` (авиакомпания сегмента и обновление сегментов на месте `DetailsUpdate`, api PR №36)
> **Источник требований:** изменение SDD `add-flight-segment-number` в `tourismania/sdd`
> (`openspec/changes/add-flight-segment-number/`: proposal, дельта спеки `offers/flights`, design, tasks),
> принято в [sdd PR №28](https://github.com/tourismania/sdd/pull/28).
> Этот файл — краткая выжимка для api; при расхождении прав SDD.

## Контекст

Номер рейса — то, по чему клиент находит свой рейс в билете, на табло и в приложении авиакомпании.
Сейчас он есть только у сегмента в редакторе web и теряется при сохранении: api его не хранит. Это
последнее поле сегмента web, которого нет в api; без него web не может перейти на перелёты из api без
потери данных.

**Инварианты:**

- **Номер — у сегмента, не у перелёта.** У каждого беспосадочного сегмента свой рейс. Поле —
  `flight_number` (в web — `flightNumber`).
- **Хранится как введён.** Свободная строка до 10 символов (символы, а не байты — кириллические
  внутренние коды допустимы); формат не проверяется, регистр, пробелы и разделители не меняются
  (решение владельца, ревью sdd PR №28). Правило записи (код перевозчика + цифры) — подсказка в
  интерфейсе, а не валидация.
- **Без значения по умолчанию.** Отсутствие поля, `null` и `""` — номер неизвестен; хранится и
  отдаётся как `""`.
- **Длина — правило формы запроса** (`validate:"max=10"` в DTO, как `ManagerComment`); у домена
  правил для номера нет, `flight.New` его не проверяет.
- **Номер с авиакомпанией не сопоставляется**, уникальность в перелёте и оффере не проверяется.
- **Виден везде, где виден перелёт**, включая публичную ссылку; в ответе поле есть всегда.
- **Изменились только номера (и/или класс, авиакомпания, цена, комментарий) — обновляются на месте.**
  Номер в маршрут не входит; номера сравниваются точно (`SU1234` ≠ `su 1234`). `DetailsUpdate` несёт
  детали сегментов одним срезом `Segments []SegmentDetails{CabinClass, AirlineID, FlightNumber}`
  вместо параллельных `SegmentCabinClasses`/`SegmentAirlineIDs` (design, решение 4), `id` перелётов
  сохраняются.

## Эндпоинты

Новых маршрутов нет.

| Метод | Путь | Что меняется |
|---|---|---|
| `POST`  | `/api/v1/offers` | у `flights[].segments[]` необязательное `flight_number` (строка до 10 символов, допускает `null`) |
| `PATCH` | `/api/v1/offers/{uuid}` | то же; правка только номеров сохраняет `id` перелётов |
| `GET`   | `/api/v1/offers/{uuid}` | у `flights[].segments[]` всегда `flight_number` (строка как передана, `""` — неизвестен) |
| `GET`   | `/api/v1/public/offers/{uuid}` | то же |

## Ошибки

| Условие | Ответ |
|---|---|
| Длиннее 10 символов | `400 validation failed`, `meta` `{"FlightNumber":"max"}` |
| Не строка (число, объект, массив) | `400 field "…" has the wrong type` |
| `flight_number` у перелёта, `flightNumber` в сегменте | `400` unknown field |

## Хранение

Миграция `023_add_offer_flight_segments_flight_number`:
`offer_flight_segments.flight_number VARCHAR(10) NOT NULL DEFAULT ''`; уже сохранённые сегменты
получают `''`. Без `CHECK` на формат. Совместима со старым кодом — можно накатить до выкладки. Down —
`DROP COLUMN` (теряются только номера рейсов).

Обновление на месте — `UpdateOfferFlightSegmentDetails` (`SET cabin_class, airline_id, flight_number`)
по `flight_id` и `sequence` в пределах `offer_id`: сегменты перелёта чужого оффера не меняются.
