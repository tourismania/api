### Перелёты (Flight) в составе Offer (issue №20)

- [ ] Создание offer с одним прямым перелётом (без пересадки)
- [ ] Создание offer с перелётом с пересадкой (2+ сегмента) — offer и flights в одной транзакции
- [ ] Невалидная хронология сегмента (`arrival_at <= departure_at`) → 400, offer не создаётся
- [ ] Разрыв маршрута (аэропорт прилёта сегмента N ≠ аэропорту вылета сегмента N+1) → 400
- [ ] Пересадка нулевой/отрицательной длительности → 400
- [ ] Несуществующий `icao` в сегменте → 400
- [ ] `PATCH` без ключа `flights` — существующие перелёты не трогаются
- [ ] `PATCH` с `flights: []` — все перелёты офера удаляются
- [ ] `PATCH` с новым набором `flights` — старые полностью заменяются (diff-then-replace)
- [ ] `PATCH` с `flights`, идентичными уже сохранённым — no-op, БД не трогается
- [ ] `GET` детального offer возвращает вычисленные `total_duration_seconds` и `layovers` (0/1/2+ пересадок)
- [ ] `GET /offers` (список) не содержит `flights`

### Цена и валюта перелёта (issue №26)

- [ ] Создание перелёта с `"price":"12345.5","currency":"EUR"` → в карточке `"price":"12345.50"`, `"currency":"EUR"`
- [ ] Нулевая цена `"0"` → в карточке `"0.00"`
- [ ] Перелёт без `price`/`currency` (прежний формат) → 400 `validation failed`, в `meta` `Price` и `Currency`
- [ ] Знаков после точки больше, чем у валюты (`"10.125"` USD) → 400, `meta: {"Price":"money"}`
- [ ] Некорректная запись цены (`"-1"`, `"1e3"`, `"12,50"`, 11 цифр в целой части) → 400, `meta` `Price`
- [ ] Цена числом JSON (`"price": 100`) → 400 `field "…" has the wrong type`
- [ ] Валюта не из справочника (`GBP`, `rub`) → 400, `meta: {"Currency":"currency"}`
- [ ] `price` внутри сегмента → 400 unknown field
- [ ] `PATCH` с тем же набором, цена в другой записи (`"100"` vs `"100.00"`) → no-op
- [ ] `PATCH`, где изменилась только цена/валюта → обновляется только цена, `id` перелётов в карточке не меняются
- [ ] `PATCH`, где изменился маршрут → набор заменяется, `id` новые
- [ ] Публичная карточка (`/public/offers/{uuid}`) содержит `price` и `currency`
- [ ] Миграция `018`: перелёты без цены удаляются вместе с сегментами; `down` удаляет столбцы

### Комментарий менеджера к перелёту (issue №31)

- [ ] Создание перелёта с `"manager_comment":"Багаж оплачивается отдельно"` → в карточке тот же текст
- [ ] Без поля / `null` / `""` → в карточке `"manager_comment":""` (поле не опускается и не `null`)
- [ ] Текст как есть: переводы строк, табуляция, пробелы по краям, `<>&`, эмодзи
- [ ] Текст, похожий на SQL (`Rock'n'roll \ "VIP"'; DROP TABLE offers; --`) → возвращается без изменений, оффер и перелёты читаются как прежде
- [ ] `\u0000` и `\u001b` в комментарии → 400 `validation failed`, `meta: {"ManagerComment":"text"}`, оффер не создан (не 500)
- [ ] Ровно 2000 символов кириллицы → 201
- [ ] 2001 символ → 400, `meta: {"ManagerComment":"max"}`, оффер не создан
- [ ] Комментарий числом / объектом / массивом → 400 `field "…" has the wrong type`
- [ ] `manager_comment` в сегменте, `managerComment` у перелёта → 400 unknown field
- [ ] Перелёт в прежнем формате без комментария → 201, комментарий `""`
- [ ] `PATCH` с тем же набором (`null` vs `""` vs без поля) → no-op, `id` не меняются
- [ ] `PATCH`, где изменился только комментарий → обновляется на месте, `id` перелётов не меняются
- [ ] `PATCH`, где комментарий удалён (без поля / `null` / `""`) → комментарий `""`, `id` не меняются
- [ ] `PATCH` с управляющим символом или длиннее 2000 → 400, ничего не меняется
- [ ] Публичная карточка (`/public/offers/{uuid}`) содержит `manager_comment`
- [ ] Миграция `019`: существующие перелёты получают `manager_comment = ''`; `down` удаляет столбец

### Справочник авиакомпаний (sdd `add-flight-segment-airline`)

- [ ] Справочник без синхронизации: `search=неизв` и `search=unknown` находят `id: 1` — `icao: null`, `name: "Unknown"`, `name_ru: "Неизвестная"`, `country: null`, `dissolved_on: null`
- [ ] Поиск по русскому и английскому названию и по названию страны (`турц`) без учёта регистра и диакритики
- [ ] `country=tr` оставляет только авиакомпании страны; `country=TUR` / `1` → 400 `{"Country":"iso2"}`
- [ ] `search=afl` не находит «Аэрофлот» по коду: по ICAO/IATA не ищется
- [ ] Две авиакомпании с одним кодом (закрывшаяся и действующая) — обе в выдаче, действующая выше; `dissolved_on` у закрывшейся
- [ ] Ранжирование: действующие выше закрывшихся; начало названия → подстрока → только страна
- [ ] Дубль и пропавшая из источника не находятся ни по названию, ни по `ids`; вернувшаяся — снова находится под прежним id
- [ ] `Al_ha` не находит `Alpha Air`: `%`, `_`, `\` ищутся буквально
- [ ] У иностранной `name_ru: ""`; в `data` нет кодов IATA
- [ ] Нормализация пробелов и `meta.search`; `search=SU` / `%20%20` / без `search` и `ids` / `ids=42&search=SU` → 400 `INVALID_SEARCH`
- [ ] `ids=42,57` без `search` → обе в порядке ранжирования, `meta.ids`; повторы не дублируют; несуществующие → `data: []`
- [ ] `ids=0` / `-1` / `abc` / `42,,57` → 400 `{"IDs":"min=1"}`; 101 id → `{"IDs":"max=100"}`
- [ ] `limit=101` → 400 `{"Limit":"max=100"}`, `offset=10001` → `{"Offset":"max=10000"}`; `abc` / `-5` → значения по умолчанию 20 / 0
- [ ] Пустая выдача → 200 `data: []`, `total: 0`; ответ с `Cache-Control: private, max-age=3600`
- [ ] `GET /api/v1/airlines/{id}`: действующая, дубль и пропавшая → 200, поля как у элемента поиска; `1` — «Неизвестная»; нет записи / `abc` / `0` → 404 `airline not found`
- [ ] Без токена → 401 (поиск и по id)
- [ ] `airlines sync --dry-run` печатает ненулевые числа и не меняет таблицу; `airlines sync` наполняет; повторный запуск не меняет ни одного `id` и не создаёт дубликатов; запись `1` не меняется
- [ ] Синхронизация: элемент перенаправлен на известную запись → дубль, сегменты не меняются; без перенаправления → пропавшая; не пришло > 10% → ошибка, ничего не записано
- [ ] Журнал аномалий: `jq 'select(.event | startswith("airline_sync."))'` выводит столько событий, сколько в строках `anomaly …` итога
- [ ] Миграция `021`: после `up` одна запись `id = 1`, следующая вставка получает `2`; две записи с одним `icao` и одним `source_id` вставляются; `up` → `down` → `up` проходит

### Номер рейса сегмента перелёта (sdd `add-flight-segment-number`)
